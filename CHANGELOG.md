# Changelog

## v0.14.0 — 2026-11-17

- Default to repository-native engineering without synthetic backlog, admission,
  packet, standard docs layout or mandatory lane-runtime installation.
- Scope formal lifecycle/runtime gates to adopted work, preserve real refusals
  and accepted contracts, and recognize authority already in the user's request.
- Align active workers, Gitflow fallback/branch guidance and runtime help;
  leave repositories without a product backlog untouched by session hooks.
- Pair with Gitflow Operator v0.2.0 for configured/detected branches, including
  `development`, `master` and custom integration names.

## v0.13.0 — 2026-11-16

- Compose the standalone Gitflow Operator as the owner of provider-specific
  GitHub and GitLab operations, while retaining Autopilot's compatibility
  launcher and lifecycle authority.
- Add full-suite and lifecycle-validator CI for pull requests and releases.
- Refresh the source-bound verification evidence for the changed Gitflow test
  contract.
- Publish the standalone framework at
  [guillaume-galp/gitflow-skill](https://github.com/guillaume-galp/gitflow-skill).

## v0.12.0 — 2026-11-13

- Add risk-scaled Direct, Managed and Governed delivery lanes with local CLI
  execution, revision-bound working evidence, verification and completion.
- Keep admitted/legacy packet authority and frozen product history unchanged;
  consequential triggers and authority refusals cannot downgrade to local work.
- Align active skills, agents and entry instructions; include a lane usage guide.
- Permit human control-renewal records for bounded delivery tasks without
  synthetic stories; preserve prior evidence and promotion history.

## v0.11.0 — 2026-11-13

- Add reproducible, provenance-bearing framework packages and read-only
  distribution drift checks.
- Preserve the user-managed credential preflight as an external overlay.
- Resolve Gitflow commands from the target workspace before falling back to
  `PATH`.
- Keep historical slash commands as aliases to current skills.
